**no data content retrievable from public.**

## 4. Security hardening (out-of-band)

- Access restrictions: chat app allows team IP only; API app allows team IP + ACA env
  egress IP + App Service plan outbound IPs (server-side calls from chat/streamlit break
  without those); streamlit ACA ingress allows team IP only. Same rules on both scm sites.
- Entra ID Easy Auth: chat app (authsettingsV2) + streamlit ACA (`az containerapp auth`).
  App registrations `copilot-chat`, `copilot-streamlit` in the tenant. GOTCHA: app
  registrations created via `az ad app create` need
  `web.implicitGrantSettings.enableIdTokenIssuance=true` patched via Graph (`az rest`)
  or every login fails at the callback with `AADSTS700054` → 401.
- SCM/Kudu basic auth is disabled via the **child resource**
  `Microsoft.Web/sites/<app>/basicPublishingCredentialsPolicies/{scm,ftp}` with
  `properties.allow=false` (it is NOT a site property — patching the site is silently
  ignored). FTP publishing is also off (`ftpsState=Disabled`).
- API bearer auth: app registration `copilot-api` (appRole `API.Access`, identifierUri
  `api://<client-id>`), backend client `copilot-backends` (secret in vault as
  `copilot-backends-secret`). UI backends attach tokens via `ui/api_auth.py`
  (`API_AUTH_TENANT_ID/CLIENT_ID/CLIENT_SECRET/SCOPE` env; chat uses a KV reference,
  streamlit uses the ACA secret store).

## 5. Keyless data plane (Entra-only)

- AI Search, Cosmos DB, Document Intelligence and OpenAI(writic) are accessed entirely
  via Entra tokens — `disableLocalAuth=true` on Search/Cosmos/DI. The vault secrets
  cogsearch-admin-key/cosmos-key/di-key are DEAD material (kept only for rollback).
- The switch is `AZURE_CLIENT_ID` (uami client id, already in app settings for the AML
  SDK): when set, `env_vars.get_entra_credential()/get_entra_token()/search_auth_headers()`
  are used everywhere; when unset (local dev), key auth is the fallback.
- uami RBAC: Search Index Data Contributor + Search Service Contributor (ARM); Cosmos
  **data-plane** role assignment (`az cosmosdb sql role assignment create`, NOT
  `az role assignment`); Cognitive Services User (DI); Cognitive Services OpenAI User
  (writic). AML compute carries the same uami (compute identity UserAssigned).
- GOTCHAs (found the hard way):
  - ai_search.bicep ships `authOptions: {apiKeyOnly: {}}` which silently 403s all Bearer calls until flipped to `aadOrApiKey`.
  - Search auth headers must be built per request — module-level `default_headers` freezes the token and breaks after expiry/role propagation.
  - Cosmos PATCH responses may return the OLD value — re-GET after a minute.
  - The Cosmos built-in data-plane roles do NOT include database/container CREATE permissions — pre-create the `prompts` and `logs` containers via control plane (`az cosmosdb sql container create`, partition key /categoryId).
  - The app's Cosmos clients are module-level singletons that freeze a failed init until restart — restart the API app after creating containers.
  - EastUS refused Cosmos account creation ("ServiceUnavailable: high demand") — the account lives in **EastUS2**; try eastus2 before eastus for new Cosmos accounts.
- Keys that remain by design: writic-resource key1/key2 (Writic product dependency; the
  app itself uses Entra), devst file-share key (App Service SMB mount requires shared
  key), Vision key (only used by the optional AzureComputerVision enhancement in call_gpt4v).

## Fix log (2026-09-14, three UI-reported errors)

- **ACA egress IP correction (root cause of streamlit 403 + Ingestion TypeError):** the
  Container Apps workload egress IP is **<ACA_EGRESS_IP>** (verified via `az containerapp
  exec` + curl), NOT the environment's `staticIp` (<ACA_STATIC_IP>) — both are now in the
  API access-restriction allowlist. If the ACA app gets 403 again, re-verify the egress
  IP with exec; it may change if the environment is recreated.
- **search-stream ERROR tuple bug (root cause of chainlit "cannot unpack non-iterable
  NoneType"):** api.py put a 3-tuple `("ERROR", e, None)` into the steps queue while the
  streamer unpacks 2-tuples — any search-thread exception (e.g. querying a non-existent
  index) crashed the stream mid-flight and surfaced as an unrelated unpack error in the
  chat UI. Fixed to a 2-tuple; the ERROR step now reaches the client, which displays the
  real error. NOTE: the chat UI's default index is `mm_doc_analysis`, which does not
  exist — set the real index in the chat with `cmd index` (available: rag-test, rag-test2).

## AML ingestion path — FIXED and fully verified (2026-09-14, addendum)

The AML path had never worked; three stacked root causes, all found empirically and fixed:
1. **Subnet delegation blocked node allocation** ("Allocation failed as subnet has delegation
   to external resources") — the Plan A subnet `snet-aml` was created with a
   `Microsoft.MachineLearningServices/workspaces` delegation; AML compute subnets must
   have NO delegation. Delegation removed; nodes allocate fine now.
2. **Environment used AML's curated Python 3.8** ("TypeError: 'type' object is not
   subscriptable" from modern azure-search-documents) — upstream `Environment.from_pip_requirements()`
   builds on the 3.8 base. Fixed: `Environment.from_docker_image()` from the ACR API image
   (Python 3.10, same runtime as local_job). GOTCHA: `DOCKER_REGISTRY_SERVER_URL` is NOT
   injected as a container env var under managed-identity image pulls — the
   `AZURE_CONTAINER_REGISTRY` app setting (AZURE_ prefix → also propagates to job env) is
   the correct source. Stale environments under a name cannot be re-registered — bump the
   env name (`self.env_name`) when changing its definition.
3. **Same-value linuxFxVersion PATCH does not restart the App Service container** (hit
   twice this session) — always stop/start after rebuilding the API image.

Also: STANDARD_D2_V2 is retired (quota 0/6) — the cluster now runs STANDARD_D2S_V3
(DSv3 AML quota 6). Cluster idle scale-down tightened 40min → **10min** as a cost guard.

**End-to-end verified:** job ran inside the ACR docker image (python3.10 in job logs),
ingested London_Brochure on the AML path (datastore mount via private endpoint, Entra
keyless, DI, index upload), search on `test-aml` returns grounded content, and the
cluster scaled back to 0 nodes within 10 minutes of job completion. Total node time for
the verification: ~25 minutes ≈ $0.04.
